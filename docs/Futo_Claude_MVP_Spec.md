## 0. Claude Codeへの最重要指示

あなたはこのリポジトリでiPhoneアプリ「ふと」を実装する開発エージェントです。

**一度に完成版を作らないでください。本書のPhase 0から着手し、Phase 1の最小試作までで停止してください。Phase 2以降は、利用者が実機で試してから別途依頼します。**

最初の納品は「SwiftUIで中心体験が動き、実機では選択したアプリへの制限を試せる」状態です。最初から自動一時解除を完成させる必要はありません。画面が動くことと、OSによる制限が動くことを明確に区別してください。

- 既存のREADME、仕様書、AGENTS.md、Xcodeプロジェクト、Gitの変更状況を最初に確認する。
- 完成版仕様と競合する初期範囲については、本書のスコープを優先する。全体構想の内容を削除する指示ではない。
- 既存アプリがあれば活用し、無断で作り直さない。利用者の変更を上書きしない。
- 足りない設定・署名・実機作業は具体的な手順として示す。Appleアカウントの秘密情報を求めない。
- 細かい実装判断は自律的に進める。新しい有料サービス、製品範囲変更、不可逆な操作は勝手に追加しない。
- 未実装の機能を、見た目だけ実装して動作するように表示しない。
- ビルド結果、シミュレーター検証、実機検証を分けて報告する。未実施を成功扱いしない。
- 公開、TestFlight配布、App Store提出は今回行わない。リモートへのpushは別途指示がある場合のみ。

## 1. 何を作るのか

### 1.1 名前と目的

アプリ名：**ふと**  
コンセプト：**「ふと開く」から、「ふと気づく」へ。**

目的なくスマホを開く前に少し立ち止まり、自分で使い方を選ぶためのアプリ。スマホを使った人を責めたり、利用時間の少なさを競ったりしない。

最終的に大切にするのは、アプリ内に長く滞在してもらうことではなく、画面の外の時間を本人が納得して過ごせること。

### 1.2 初版で確かめること

1. やさしい日本語の問いかけが負担にならないか。
2. 「目的を選ぶ → 少し待つ → 自分で選ぶ」が自然に操作できるか。
3. Family Controls／Managed Settingsで選択した対象を実機で制限できるか。

初版は開発者本人向けの試作品。一般公開できる完成品や、解除を防止できる強制的な管理アプリとして扱わない。

## 3. 段階と停止条件

### Phase 0：外部設定なしで動く中心体験

Screen Timeを呼ばないデモ実装で、説明、ホーム、目的選択、待機、最終選択、履歴を作る。実際のアプリ制限や解除は行わない。

完了条件：シミュレーターで一連の流れが操作でき、記録が再起動後も残る。デモであることが明確。

### Phase 1：実機で制限を開始・終了できる最小試作

個人向け認証、アプリ選択、Managed Settingsによる制限を接続する。Phase 0の画面とデータを共用し、別のアプリを作らない。

完了条件：権限のある実機で選択アプリにシールドが表示され、本人が「制限を終了」すると、そのアプリに対する本アプリの制限が外れる。

署名やCapabilityなど利用者の操作が必要な場合は、実装可能な部分まで仕上げ、残る操作と実機確認項目を示す。Phase 0までしか検証できていない場合は、その状態を明記する。

**Phase 1までで停止する。実機の感想を得る前にPhase 2を実装しない。**

### Phase 2：次回の技術検証のみ（今回対象外）

将来は「待機 → 対象だけ一時解除 → 自動再制限」を追加したい。ただし次の検証が必要。

- Device Activityの利用時間しきい値とスケジュールの違い。
- 既存利用時間の混入を避け、その一時利用に対応する計測ができるか。
- バックグラウンド、強制終了、再起動、日付変更時の復帰。
- 監視登録失敗時に解除しない手順と、重複・古いイベントの排除。
- 必要な拡張、App Groups、共有状態、イベント処理の最小設計。

Appleの監視スケジュールには最短15分の制約がある。5分の実利用と、解除から5分の経過は別物。実現できない挙動を通常のTimerや通知で代用して、自動再制限できたと説明しない。15分制約だけで実利用5分が不可能とも断定しない。

## 4. 初版の体験と意図的な制約

### 4.1 初回

1. 「ふと」の短い説明を読む。
2. 「実機で設定する」または「デモで試す」を選ぶ。
3. 実機では権限説明後、本人向け認証を要求する。
4. 制限したいアプリを選び、保存する。
5. ホームから明示的に「制限を始める」を押す。

対象選択や初回認証だけで勝手に制限を開始しない。初版は必要なアプリを除外する複雑な許可リストを作らず、制限したいアプリだけを個別選択する。

### 4.2 制限中

1. 対象アプリを開くとOS標準シールドが表示される。
2. 利用者がホーム画面などから手動で「ふと」を開く。
3. 「使う前に、ひと呼吸」から目的選択へ進む。
4. 目的を選ぶか「答えずに進む」を押す。
5. 3分待つ。バックグラウンドや画面ロック中は停止する。
6. 「今も使いたいですか？」で次のどちらかを選ぶ。

| 選択 | 初版の動作 |
| --- | --- |
| 今はやめる | 見送りを記録しホームへ戻る。制限を維持 |
| 使いたい | 利用希望を記録しホームへ戻る。制限は維持 |

「使いたい」の後は次の案内を表示する。

> 利用したい気持ちを記録しました。この試作では、一時解除はまだできません。使う場合は、ホームの「制限を終了」から終了できます。

「使いたい」を「少し使う」と表示しない。解除していないのに、利用できると思わせない。

### 4.3 手動で制限を終了

ホームの「制限を終了」から確認ダイアログを開く。

> 選んだアプリの制限を終了しますか？ この試作では、自動で再開されません。

「制限を終了」「キャンセル」を用意する。終了後は本アプリが管理する対象のシールドを解除する。通常のScreen Timeなど他の仕組みの制限まで解除できるとは説明しない。

手動終了はホームからいつでも行える。この初版では解除不能を目指さず、技術検証と操作の評価を優先する。手動終了を待機後の「一時解除」や「実際の利用」として集計しない。

| 項目 | 方針 |
| --- | --- |
| 開発 | Mac、Xcode。コード編集はVS Code＋Claude Codeとの併用を想定 |
| 言語・画面 | Swift、SwiftUI |
| 最低OS | iOS 17を初期値。既存構成とSDKの対応を確認 |
| 状態管理 | SwiftUIの標準機構。小さなサービスと明示的な状態遷移 |
| 履歴 | SwiftData、端末内のみ |
| 設定 | UserDefaults。選択トークンは対応するCodable形式を使用 |

アプリはiPhone用。Macは開発端末であり、Mac向けアプリを作る依頼ではない。

拡張ターゲットが不要なPhase 1ではApp Groupsも導入しない。将来のためだけの大きな抽象化、汎用プラグイン機構、複数ストレージ層を作らない。

## 6. 画面仕様

### 6.1 初回説明

- タイトル：「ふと」
- 見出し：「使う前に、ひと呼吸。」
- 説明：「スマホを開く前に、何に使いたいか確かめる。自分のペースで、使い方を選ぶためのアプリです。」
- 初版説明：「この試作では、アプリの制限と、使う前の振り返りを試せます。一時解除はまだできません。」
- 操作：「実機で設定する」「デモで試す」

### 6.2 ホーム

上から順に、アプリ名、動作モード、権限・設定状態、制限対象、中心操作、今日の記録を配置する。

状態に応じた表示：

- デモ：「デモモード：実際のアプリは制限しません」
- 権限なし：「制限にはアクセスの許可が必要です」
- 対象なし：「制限したいアプリを選んでください」
- 有効設定あり：「選択したアプリへの制限を設定しています」
- 制限終了：「制限はオフです」
- エラー：「設定を確認できませんでした。もう一度お試しください」

主操作は状態に合わせて「許可する」「アプリを選ぶ」「制限を始める」「使う前に、ひと呼吸」を切り替える。制限中のみ「制限を終了」を副操作として表示。

表示する数値は「今日の見送り」と「今日の利用希望」だけ。使用時間、節約時間、対象アプリを開こうとした回数は表示しない。

権限や適用設定を照合した表示であり、OS上で実際にシールドが出ていることを常時検知できると説明しない。

### 6.3 目的選択

- 見出し：「今、どんなことに使いたいですか？」
- 単一選択：「連絡」「調べもの」「気分転換」「なんとなく」
- 選択後：「ひと呼吸おく」
- スキップ：「答えずに進む」
- 戻る操作を許可する。

自由入力は作らない。回答をスキップしても待機時間や操作上の扱いを変えない。

### 6.4 待機

- 見出し：「少しだけ、立ち止まってみましょう。」
- 補足：「画面を閉じると、待機は一時停止します。」
- 残り時間を分・秒で表示。標準3分。
- 滑らかで控えめな進捗表示。派手な演出や音はなし。
- 中断してホームへ戻れる。
- 待機が終わるまでは最終選択へ進めない。

中断時は途中のセッションを保存する。ホームに「ひと呼吸を再開」を表示し、再開では同じセッションを使う。「この振り返りを終了」も用意し、その場合は中断として記録する。

### 6.5 最終選択

- 見出し：「今も使いたいですか？」
- 「今はやめる」「使いたい」
- 補足：「この試作では、どちらを選んでもアプリの制限は解除されません。」

どちらも同じ程度に押しやすくし、見送りだけを過剰に目立たせない。完了後の文言は「記録しました。」を基本とする。

### 6.6 履歴

日時、本人が選んだ目的、結果を新しい順に表示する。

- 結果：「今はやめる」「使いたい」「中断」
- スキップした目的：「回答なし」
- 空状態：「まだ記録はありません。」
- 継続中は完了履歴と分け、ホームから再開できる。
- 実機とデモを混ぜず、現在モードの履歴だけを表示する。

### 6.7 設定

- 権限状態と再確認。
- 制限アプリの変更。
- デモモードの切り替え。
- 記録の削除。
- 初版の制約説明。

制限中・待機中の対象変更は初版では禁止し、「制限を終了してから変更してください」と案内する。デモへ切り替える前にも実際の制限を終了し、確認できない場合は切り替えを保留して理由を示す。

記録の全削除ではセッションを削除するが、制限設定は変更しない。確認文にその違いを明記する。進行中セッションの削除時は、先に中断扱いで閉じてから削除する。

## 7. 日本語・見た目

温かい白を基調とし、落ち着いた緑を主なアクセントにする。薄い青は必要な箇所だけ。標準フォント、十分な文字サイズ、控えめな角丸と余白を使う。

コンセプト画像は雰囲気の参考であり、背景写真・山・植物・本などをすべてアプリ内に再現する必要はない。初版は標準コンポーネント中心に読みやすく作る。

- 「失敗」「依存症」「また使ってしまいましたね」などの評価をしない。
- 「すごい！」「えらい！」などの過剰な称賛もしない。
- 連続日数、ランキング、赤い警告数値を入れない。
- 絵文字を使わない。必要なアイコンはSF Symbols。
- Dynamic Type、VoiceOver、十分なタップ領域に対応する。
- 長い日本語や文字拡大でボタンが隠れない。スクロールで操作に到達できるようにする。
- 色だけで状態を伝えない。ダークモードでも文字と背景の可読性を維持する。

## 8. 状態管理と待機

### 8.1 独立した状態

以下を1つの巨大なenumに詰め込まず、必要な範囲で分ける。

| 状態 | 例 |
| --- | --- |
| モード | demo / device |
| 権限 | 未確認 / 許可 / 拒否・取消 / エラー |
| 制限設定 | 無効 / 有効設定あり / 確認不能 |
| セッション | なし / 目的選択 / 待機 / 選択待ち / 完了 / 中断 |

主な遷移：目的選択 → 待機 → 選択待ち → 見送りまたは利用希望。中断・再開は同じIDで行う。最終操作の連打で重複保存しない。

### 8.2 待機時間の計測

- 生産用の初期値は180秒。
- `scenePhase == .active` の区間のみ経過させる。
- 前面実行中は単調増加する時計を使い、Timerの呼び出し回数を秒数にしない。
- 非アクティブ化時に残り時間を保存し、再開後はそこから進める。
- 時計変更やバックグラウンド時間で待機を飛ばさない。
- 終了・クラッシュからの復帰で、保存していない時間を勝手に加算しない。多少待機が延びる保守的な復帰を許容する。
- 二重タイマー、負の残り時間、バックグラウンドからの二重完了を防ぐ。
- Debug限定で5秒のテスト設定を用意する。本番ビルドに短縮ボタンを出さない。

権限を失った場合、待機は中断して案内する。アプリを再度前面表示した際は、権限と本アプリの制限設定を再確認する。

## 9. データ

### 9.1 Session：SwiftData

| フィールド | 内容 |
| --- | --- |
| id | UUID。一意 |
| mode | demo / device |
| startedAt | 開始日時 |
| purpose | contact / research / break / noReason / 未回答 |
| requiredWaitSeconds | 開始時の待機時間 |
| remainingWaitSeconds | 保存済みの残り時間 |
| phase | 目的選択 / 待機 / 選択待ち / 完了 / 中断 |
| outcome | deferred / wantsToUse / interrupted / 未確定 |
| completedAt | 完了・中断日時。進行中はなし |

対象アプリ名や詳細な利用時間は保存しない。目的は列挙値で保存し、日本語表示と分離する。

### 9.2 Settings：UserDefaults等

初回説明済み、現在モード、実機の対象選択、制限を有効にする意図を保存する。権限の有無は保存値だけを信用せずOSから確認する。適用状態を確認できない場合は、有効だと断定しない。

FamilyActivitySelectionのトークンは不透明な識別情報として扱う。名前・bundle ID・全アプリ一覧を任意に取得できる前提にしない。SDKが提供するラベル表示を使用し、難しい場合は選択数を表示する。

初版は端末内のみ。独自クラウド同期・外部ログ送信・解析SDKはなし。端末のバックアップからの復元も初版の保証には含めない。

## 10. Screen Time実装ルール

- 個人利用なので `.individual` 認証を使う。保護者・子ども管理フローを作らない。
- Family Controls Capability、Bundle ID、署名設定は現在のXcodeとApple公式資料で確認する。
- FamilyActivityPickerからアプリ単位の選択だけを採用する。カテゴリやWebサイト選択が含まれる場合は、対象外だと明示し、アプリの選び直しを案内する。黙ってカテゴリ制限を適用しない。
- 管理対象を本アプリ用ManagedSettingsStoreに限定する。
- 制限を始める前に権限と対象があることを確認する。
- OS標準シールドを使う。そこから本体へ自由に遷移できる前提にしない。
- 一般的なアプリと同様に本人が権限を取り消せることを前提にする。削除不能・解除不能と説明しない。
- 権限を取り消した後に、保存済みの「有効」だけで制限中と表示しない。
- 選択したアプリに対する本アプリの制限だけを解除する。
- OS再起動などに関して、試験なしで維持・復帰を保証しない。
- 個人向けUIの試作と、実機の認証・制限の可否を混同しない。署名条件が満たせなくてもデモは使える。

開発用署名と配布用権限申請は別。TestFlight／App Store配布へ進む際はFamily Controls配布用権限を確認する。将来拡張を追加する場合は拡張側の要件も確認する。開発者登録の状況や必要なプランは推測せず、実際のアカウント・Xcodeの状態に合わせて案内する。

## 11. ファイル構成の目安

既存構成があればそれを優先する。新規なら以下程度の小さな構成でよい。

```text
Futo/
  App/              # 起動・依存の生成
  Models/           # Session、目的・結果の定義
  Services/         # Screen Time、デモ、待機の処理
  Views/            # 説明、ホーム、目的、待機、最終選択、履歴、設定
  Resources/        # Assets、日本語リソース
FutoTests/
docs/
  SETUP.md
  IMPLEMENTATION_STATUS.md
```

Screen Timeへの依存だけは、実機用とデモ用を差し替えられる小さな境界にする。SwiftData全体を覆う汎用Repositoryは不要。ViewにOS権限処理や待機時間計算を直接詰め込まない。

デモ用の架空アプリと実機トークンを混ぜない。デモで設定した「制限中」を、実機へ切り替えたとき適用済みとして引き継がない。

## 12. 実装の作業順

1. 既存コード・仕様・Git差分・開発環境を確認する。
2. 今回の範囲と、Phase 0／1の短い作業計画を提示する。
3. ビルド可能な最小SwiftUIアプリを用意する。
4. Sessionと待機の状態遷移を実装する。
5. デモで説明から履歴まで通す。
6. 重複保存、待機停止・再開、記録削除を確認する。
7. 個人認証、対象選択、制限の開始・終了を接続する。
8. 実機で必要な署名・Capability設定を文書化する。
9. 実行できるビルド・テストを実行し、結果を記録する。
10. Phase 0／1の達成状況と、利用者の次の操作を報告して停止する。

一時解除がないことを理由に全体を作り直したり、勝手にShortcuts方式へ変更したりしない。

## 13. 検証

### 13.1 自動テストで守ること

実時間で3分待たず、時計を差し替えて検証する。

- 前面実行中のみ残り時間が減る。
- 非アクティブ中は減らず、再開後に続く。
- 待機完了前に最終選択へ進めない。
- 再開しても新規Sessionが増えない。
- 完了操作を2回呼んでも結果が重複しない。
- 目的スキップと回答済みで同じ待機が適用される。
- 日別件数は現地カレンダーを使い、デモと実機を分離する。
- 保存・復帰で結果と残り時間が保持される。

単に画面文言と同じ文字列を照合するだけのテストを大量に作らない。

### 13.2 シミュレーター確認

- デモモードの明示。
- 初回説明、目的選択、スキップ、待機、見送り、利用希望、履歴。
- アプリ切り替え、途中復帰、連打、全削除。
- 小さいiPhone画面と文字サイズ拡大で主要操作に到達できる。
- デモから実際の制限が発生しない。

### 13.3 実機確認

| 操作 | 期待結果 |
| --- | --- |
| 認証をキャンセル | 制限されず、再試行できる |
| 対象未選択で開始 | 開始せず選択を案内 |
| 1アプリを選択して開始 | 対象にOSシールドが出る |
| 対象外アプリを開く | 本アプリの制限で妨げられない |
| 制限中に「ふと」を開く | 自分のアプリが利用できる |
| 目的選択から見送り | 制限が継続する |
| 「使いたい」を選ぶ | 利用希望のみ記録し、制限は継続する |
| ホームで制限終了 | 本アプリの対象制限が外れる |
| 権限を設定から取り消す | 復帰時に状態が修正される |
| アプリを強制終了して開く | 設定と進行中セッションを再確認する |
| 端末を再起動する | 実際の制限状態を検証し結果を記録する |

シールド表示、強制終了、再起動は目視の実機確認を行う。実機を操作できない場合はチェックを未実施にして利用者へ渡す。
