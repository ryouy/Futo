# Phase 5 セットアップ（Google Drive バックアップ）

Phase 4 の設定（Firebase・Google OAuth クライアントID・`Phase4Config.plist`）が済んでいる前提です。バックアップは**アプリから Google Drive に直接**保存します。Vercel のサーバーは通りません（サーバー側の変更・環境変数は不要）。無料です（Drive の容量は、利用者本人のGoogleアカウントのものを使います。バックアップは数百KB程度の想定）。

## 1. Google Cloud で Drive API を有効にする
1. <https://console.cloud.google.com> で、Phase 4 と同じプロジェクト（`futo-share`）を選ぶ。
2. **APIとサービス → ライブラリ → 「Google Drive API」→ 有効にする**。
   - 有効にしないと、アプリに「Google Drive APIが有効になっていません」と出ます。

## 2. OAuth 同意画面にスコープを追加する
1. **APIとサービス → OAuth 同意画面 → データアクセス（Data Access）→ スコープを追加または削除**。
2. 手動で `https://www.googleapis.com/auth/drive.appdata` を追加して保存する（「Drive上のアプリ専用の設定データを表示および管理」）。
   - このスコープは、アプリ専用の隠しフォルダだけを対象にします。ほかのDriveのファイルは、見えません。
3. 公開前（テスト状態）は、**テストユーザー**に自分のアカウントが入っていることを確認する。

## 3. アプリ側
追加の設定はありません（`Phase4Config.plist` を使い回します）。ログイン中に、**設定 → 共有 → バックアップ → 「バックアップを有効にする」** を押すと、Google の許可画面（Drive のアプリ専用領域）が出ます。

## 4. 実機での確認手順
1. バックアップを有効にする → 許可画面で、ログインと同じアカウントを選ぶ。
2. 今すぐバックアップ → 「バックアップしました」と最後のバックアップの日時が出る。
3. Drive の「アプリの管理」に、ふと（Futo）が出る（アプリ専用データの容量が表示される）。
4. 記録を数件増やすか削除し、「バックアップから戻す」→ 追加される件数を確認 → 戻す。
5. 同じ操作をもう一度しても、記録が重複しない。
6. 別の端末（または再インストール）で、ログイン → バックアップを有効にする → 戻す。制限の対象と通知の許可は、設定し直しになる。
7. Driveの許可を取り消す → Google アカウントの「サードパーティのアクセス」からも消えている。
8. Driveのバックアップを削除 → 「バックアップはありません」になる。

## 仕様のポイント
- **入るもの**：実機の、終わったひと呼吸の記録、朝夜の振り返り、設定値、テーマ・言語。
- **入らないもの**：Screen Time の許可・制限の対象（OSのトークン）、進行中の一時解除、通知の許可、ログイン情報、デモモードの記録、途中のひと呼吸。
- **復元は追加だけ**：端末にある記録は、消さない・上書きしない。同じ記録（ID）は重複しない。
- **手動のみ**：自動の同期・定期バックアップはしません（別フェーズ）。
- **許可はKeychain**：Drive の更新トークンは端末のKeychainにだけ置き、サーバーへは送りません。ログアウトで端末から除きます（Drive上のバックアップは残ります）。
