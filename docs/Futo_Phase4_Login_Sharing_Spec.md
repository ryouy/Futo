## 0. 実装エージェントへの指示

Phase 3までの機能を維持し、任意ログイン、Webリンク共有、フレンド追加・限定共有を段階的に追加する。本書が今回のPhase 4の範囲を定める。

- ユーザー報告ではPhase 3は完了。既存コード・テスト・設定を確認し、実際の実装状況を確かめてから着手する。
- 最初にAGENTS.md、README、既存仕様、Git差分を確認する。利用者の変更を上書きしない。
- 4A → 4B → 4Cの順に実装・検証する。中間報告を挟み、本書の範囲内は継続してよい。一度に全部を未検証で完成扱いしない。
- 各段階を独立した変更単位にし、実装と検証の進捗を記録する。
- 細かな実装判断は自律的に進める。有料プランへの変更・新規契約・広告導入は行わない。
- Vercel HobbyとFirebase Sparkを初期構成とする。必要機能が無料構成で成立しない場合は、代替案と費用が発生する条件を説明する。勝手にBlazeへ変更しない。
- 本書は実装依頼であり、App Store提出やリモートへのpushの指示ではない。公開デプロイは公開内容・環境変数・接続先を整えた上で、既存の利用者の指示範囲に従う。
- Firebase／Google／Apple／Vercelの利用者操作が必要なら、作成・設定する項目、値の入手元、設定先を具体的に案内する。
- 未設定環境では既存の個人機能を起動できるようにする。架空のオンライン成功を返さない。

## 1. 製品の原則

**個人利用にログインは不要。共有・フレンド機能を使いたい人だけ登録する。**

「ふと」はスマホとの付き合い方をやさしく整えるアプリ。共有は監視・競争・利用継続の圧力を生まないことを重視する。

- 起動、制限、待機、一時解除、利用後確認、朝夜の振り返り、端末内統計、通知設定は、未ログインでも従来どおり使える。
- 初回起動でログイン画面を強制表示しない。
- Googleログインは、個人の全履歴を外部送信する同意とは扱わない。
- メールアドレス・Google上の実名・顔写真は、相手へ自動公開しない。
- 共有は手動。プレビューで内容と公開範囲を確認してから公開する。
- 個人のログ・気分・設定・制限トークンは自動同期・公開しない。
- ランキング、連続記録、既読、オンライン状態、共有催促は作らない。

## 2. 共有方法を分ける

| 種類 | 閲覧者 | ログイン | 役割 |
| --- | --- | --- | --- |
| Webリンク共有 | リンクを知っている人 | 作成者のみ必要。閲覧者は不要 | アプリなしで統計を見せる |
| フレンド招待 | 招待を受けた人 | 申請・承認に必要 | 双方同意でフレンドになる |
| フレンド限定共有 | 作成者が選んだ承認済みフレンド | 必要 | アプリ内で限定共有する |

Webリンクは「誰でも検索できる一般公開」とは異なるが、特定の相手に本人確認して限定する方式ではない。リンクが転送されると転送先も見られる。この説明を公開前に示す。

フレンド招待リンクと統計共有リンクは、別URL・別トークン・別データとして扱う。統計リンクを開いてもフレンドにならない。

## 3. 段階

### 4A：任意ログインとアカウント管理

- Google Sign-In＋Firebase Authentication。
- 自動UID、表示名、ログアウト、アカウント削除。
- ログイン前後・ログアウト後もローカル機能が動く。
- アカウント切り替え時に共有データが混ざらない。

### 4B：Webリンク共有

- 統計のプレビュー、公開項目選択、期限選択。
- ランダムリンク、QR表示、iOS共有シート。
- Vercel上でログイン不要の統計ページを表示。
- 共有一覧、公開取消、リンク再発行。

### 4C：フレンド

- 期限付き招待リンク・QR。
- 招待プレビュー、申請、招待者の承認。
- フレンド一覧、解除、ブロック、通報。
- 選んだフレンドへの振り返りカード共有。

### 今回含めない

Driveバックアップ、複数端末の個人履歴同期、広告、課金、AI、DM、自由コメント、画像投稿、アドレス帳の取得、ユーザー検索、フレンド追加通知、プッシュ通知。

Appleでサインインは一般公開前の対応事項として設計を残すが、今回の非商用試作の必須実装はGoogleログイン。未実装のAppleログインボタンは表示しない。4.8の公開要件を満たした完成品とは説明しない。

| 領域 | 初期構成 |
| --- | --- |
| iOS | 既存Swift／SwiftUIアプリ |
| 個人データ | 既存のSwiftData等。従来どおり端末内 |
| 認証 | Firebase Authentication＋Google Sign-In |
| サーバー | Vercel Functions、Node.js、TypeScript |
| Web | Next.js＋TypeScriptを第一候補。既存Webがあれば活用 |

Cloud Functions for Firebase、Cloud Storage、電話番号SMS認証、Firestore TTL機能は今回使わない。Vercel側のAPIで認証・公開範囲・期限・削除を処理する。

GitHubにはコードだけを保存する。暗号化したユーザーデータをGitにコミットしたり、共有のたびにVercelへ再デプロイしたりしない。データはFirestore、Web表示は1つの共通ページで出し分ける。

モノレポならWebを `web/` 等に配置し、VercelのRoot Directoryを文書化する。既存のiOS構成を移動する必要がなければ移動しない。

## 5. GoogleログインとID

### 5.1 入口

共有・フレンドタブまたは設定から「共有を使う」を選んだときだけログインを案内する。

説明：

> 共有を使う場合だけ、ログインが必要です。スマホの記録は、共有を選ぶまでこの端末に保存されます。

「Googleでログイン」と「今はしない」を用意する。キャンセル・通信エラーでも個人機能に戻れる。

### 5.2 認証

Google Sign-Inで得た認証情報をFirebase Authenticationへ渡す。アプリの内部IDにはFirebase UIDを使用する。Googleのメールアドレス、表示名、クライアントが送るUIDだけを本人確認に使わない。

アプリからサーバーへはFirebase IDトークンをAuthorizationヘッダーで送る。サーバーはAdmin SDKで署名・対象プロジェクト・期限を検証し、必要な操作では失効確認も行う。GoogleアクセストークンとFirebase IDトークンを混同しない。

未ログイン個人利用のためだけに匿名Firebaseアカウントを勝手に作らない。

### 5.3 プロフィール

- 初回ログインで内部UIDを自動付与し、プロフィール設定へ進む。
- 公開する表示名は本人が入力。初期値は「ふとのユーザー」等の中立的な仮名。
- 1〜20文字。空白だけ、制御文字、過度な改行などを拒否する。
- Googleの実名、メール、写真を自動転記しない。
- プロフィール画像や自己紹介文は初版対象外。
- 表示名変更は過去の統計スナップショット内の表示名を自動変更しない。
- 人を検索する公開IDは不要。招待リンク・コードでつながる。

### 5.4 オフライン・ログアウト・切り替え

ログイン状態が失効しても制限・待機を止めない。共有操作だけを再ログイン待ちにする。

ログアウトは共有を削除する操作ではない。既存の共有が残ることを明示し、「共有を管理」への導線を設ける。端末内個人履歴を残すか削除するか選べるが、どちらでも制限設定を勝手に変えない。

共有・フレンドのローカルキャッシュ、保留中の操作、認証状態はUID単位で分離し、ログアウトで除去する。別アカウントへの未送信データの自動送信を禁止。ローカル記録が残っている場合、その端末の記録を共有することをプレビューで確認する。別アカウントのクラウド履歴として自動帰属させない。

## 6. Web統計共有

### 6.1 公開する内容

初期の期間は「今週」「先週」。個人向け統計と同じ定義・現地週区切りを使い、開始・終了日とタイムゾーンを保存する。今週は共有時点までの途中経過と分かるようにする。

| 項目 | 初期選択 |
| --- | --- |
| 期間 | 必須 |
| 仮名の表示名 | オン。匿名表示も選べる |
| 解除申込数・見送り数・中断数 | オフ。まとめて選択可 |
| 利用目的の内訳 | オフ |
| 利用後の満足感 | オフ。回答件数を併記 |
| 定型のひとこと | 任意。「今週はこんな感じでした」等 |

全項目が未選択なら公開せず、選択を案内する。公開を急がせるために詳細を初期オンにしない。

以下は共有しない：対象アプリ名、トークン、詳細時刻、自由記述、気分の履歴、通知・制限設定、メール、認証情報、実測していない使用時間・節約時間。

見送り率は見送り数÷解除申込数。中断も分かる形にし、分母0なら率を出さない。満足感は回答済み件数を分母とする。未回答の補完や、利用希望・解除付与からの実利用の推測をしない。少ない・多いを善悪で評価しない。

### 6.2 プレビューと作成

プレビューには公開項目、期間、表示名、期限、リンクを知る人が見られる説明を表示する。最終ボタンは「この内容でリンクを作る」。

- サーバーがスキーマ・件数・文字数・整合性を検証する。
- 数値は端末の自己申告の集計であり、OSが証明した統計として扱わない。
- 件数は0〜100,000、内訳は非負整数、本文は用意した定型IDのみ。
- 1リクエスト最大32KiBを初期上限とし、端末の全履歴を送信しない。
- サーバーが作成時刻・所有者・期限・IDを決める。クライアントのownerUidを信用しない。
- 作成リクエストに一意なidempotency keyを付け、同じ再送でリンクを増やさない。UIDと操作単位に束縛する。
- オフラインではプレビューまで。自動公開しない。「公開済み」はサーバー成功後のみ。

### 6.3 スナップショット

共有内容は作成時点のコピー。個人履歴の更新で変わらず、最新化したいときは新規作成する。既存リンクへの自動追記・追跡をしない。

初期期限は7日。1日／7日／30日から選べる。無期限は作らない。初期上限は有効なWeb共有20件／ユーザー、作成20件／日。上限はサーバー側で強制する。

### 6.4 URLと秘密トークン

URL例は設計用の仮値：`https://<共有ドメイン>/s/<token>`。

- CSPRNGで32バイトを生成し、base64url化。UIDや時刻から生成しない。
- 生トークンと内部ドキュメントIDを分離し、Firestoreには原則SHA-256ハッシュを保存する。
- トークンハッシュをキーとして正確な1件取得ができる構造にする。全件スキャン禁止。
- URL再表示のために必要な生トークンは所有者のiOS KeychainにUID別で保管する。
- 別端末・紛失などでトークンを復元できなければ再発行を案内する。新端末で同じリンクを再表示できるとは約束しない。
- 再発行は新トークンを作り、同じトランザクションで旧トークンを無効化する。
- 検証済みの許可ホストと種類だけをアプリが処理する。

QRは同じHTTPSリンクを符号化し、iOS共有シートでURLをLINEなどへ送れるようにする。LINE専用SDK、連絡先アクセス、LINEへの自動送信は不要。

### 6.5 Web表示

スマホ優先、ログイン不要。アプリの生成り・緑とゴシック体を基調にする。現在のロゴ素材があれば再利用する。広告、解析SDK、外部フォント、外部埋め込みは不要。

表示：仮名または匿名、対象期間、共有した項目、回答件数、定型文、共有時刻。小さな「ふと」の案内と通報導線を用意する。

- ページ表示・API取得のたびにサーバーが有効期限と失効を確認する。
- ページ・APIは `Cache-Control: private, no-store` 等で共有CDN・ISR・静的生成のキャッシュに残さない。
- 削除後の再アクセスを遮断する。すでに表示済みの画面・スクリーンショットを回収できるとは説明しない。
- 不正・期限切れ・削除済みは、個人情報なしの「この共有は利用できません」で統一する。
- `noindex, nofollow, noarchive` と `X-Robots-Tag`。検索除外はアクセス制御の代わりにはしない。
- `Referrer-Policy: no-referrer`。トークン付きURLを外部へ送らない。
- OGメタ情報やLINEプレビューに統計・表示名を含めず、汎用の「ふとの振り返り」を使う。
- GET、LINEのリンクプレビュー、セキュリティスキャンでは、共有や招待を変更しない。
- URLトークン・IDトークン・個人の統計をアプリログに出さない。ホスティングのURLログに含まれ得る点を確認し、保持・閲覧範囲を抑える。完全にログに残らないとは説明しない。

### 6.6 管理

作成者のみ共有一覧と取消・再発行にアクセスできる。表示するのは期間、公開項目、作成日、期限、状態。閲覧回数、閲覧者追跡、既読を作らない。

取消はサーバー成功後に完了表示。通信失敗時は「取消できていません」とし、再試行を用意する。端末内から消すだけで公開取消としない。

## 7. フレンド招待

### 7.1 招待

「フレンドを招待」で、24時間有効・成功申請1件限りの招待を発行する。招待用URLは `/i/<token>`。統計トークンとは完全に別にする。生成・ハッシュ保存はWeb共有と同じ基本方針。

QR表示、リンクのコピー、共有シートを用意する。リンクを公開SNSへ載せる前提にはしない。

### 7.2 Webとアプリ

- Webは「○○さんからの招待」と期限・「アプリで開く」を表示。メール・内部UIDは出さない。
- WebからのGETでは申請・使用済み処理をしない。
- アプリ未インストールなら案内を出す。未公開時に架空のApp Storeリンクを作らず、テスト版の導入案内と再度招待を開く手順を出す。
- インストール後に招待が自動復元されるとは約束しない。元リンクを再度開くか、コードを入力する。
- アプリ内の招待コード入力を代替として用意する。コードはランダムな英数字12文字程度、短い6桁連番は使わない。サーバーで同じ招待へ対応させ、回数制限を行う。
- Universal Linksを第一候補とし、AASA・Associated Domainsを設定する。Firebase Dynamic Linksは使用しない。
- `/i/*` をアプリで処理し、`/s/*` は原則Web閲覧のままにする。
- LINE内ブラウザなどUniversal Linksが動かない場合はコード入力へ案内する。カスタムURLスキームだけに依存しない。

### 7.3 申請と承認

1. 相手がGoogleログインする。未ログイン中は招待を期限まで保留できる。
2. 双方の表示名と共有方針を確認し、「フレンド申請」を押す。
3. サーバーが期限、残り回数、自己招待、既存関係、ブロックを検証する。
4. トランザクションで招待を消費し、申請を1件作成する。
5. 招待者がアプリ内の申請一覧から「承認」または「見送る」を選ぶ。
6. 承認後だけフレンドになる。申請中は限定共有を見られない。

招待を転送された第三者の申請でも自動承認しない。相手を見て見送れるようにする。見送り後の再招待は新しい招待を必要とする。

申請者は取り消せる。申請は7日で失効。Web共有と同様、期限はサーバー時刻で判定し、物理削除のタイミングに依存しない。

同じ2人の逆方向申請・同時承認・二重押しで関係が重複しない。UIDを正規順にしたペアキー等で一意にする。初期上限はフレンド50人、未処理申請20件、招待作成10件／日。

## 8. フレンド限定共有

初版はアプリ内だけ。Webでの限定閲覧用ログイン画面は作らない。

- Web共有と同じ統計のプレビューを再利用する。
- 公開先をフレンドから明示選択する。「全員」を勝手に初期選択しない。
- 初版の期限は30日。スナップショット形式。
- 選択された相手であっても、現在フレンドであることと双方のブロック状態を毎回検証する。
- 新しいフレンドに過去カードを自動公開しない。
- 解除・ブロック時に過去カードの相手を失効させ、再度友達になっても古い権限を自動復活させない。
- Webリンクへ変換するときは別の新規公開操作とし、フレンド限定カードのURLを公開しない。
- リアクションは今回不要。DM・自由コメントもなし。
- キャッシュ済みでも、通信なしでアクセス権を再確認できない限定カードは初版では開かない。本人の個人データはオフラインで従来どおり使える。

### 解除・ブロック・通報

解除：双方のフレンド関係を終了し、申請や共有先の権限を無効化する。

ブロック：関係を終了し、再申請・新規共有を双方方向で防ぐ。相手にブロックした事実を通知しない。解除後も自動で友達に戻さない。

通報：対象IDと定型理由だけを送る。初版では自由記述・画像添付は不要。通報者・運営だけが扱い、被通報者からは読めない。運営が確認できる手順とユーザー向け問い合わせ先を設定する。未設定なら公開前の未完了項目として残す。

## 9. サーバー・データモデル

クライアントからFirestoreを直接読ませず、今回の共有・フレンド機能はAPI経由に統一する。Firestore Rulesは原則クライアントのread/writeを拒否する。Admin SDKはRulesをバイパスするため、全APIで独立して認証・認可を行う。

| 保存対象 | 主な内容 |
| --- | --- |
| users/{uid} | 表示名、createdAt、updatedAt、active/deleting等 |
| shares/{shareId} | ownerUid、公開種別、選択項目、集計コピー、期間、作成・失効時刻、状態 |
| shareTokens/{hash} | shareIdへの対応。正確な1件参照 |
| invitations/{inviteId} | inviterUid、expiresAt、消費・取消状態 |
| invitationTokens/{hash} | 招待IDへの対応。リンク・入力コード別ハッシュ |
| friendRequests/{pairKey} | 当事者、申請方向、招待ID、pending等、期限 |
| friendships/{pairKey} | 当事者、active/removed、世代または関係ID |
| friendShares/{id} | ownerUid、集計コピー、期限、明示的な受信者と関係世代 |
| blocks/{pairKey} | 当事者ごとのブロック状態 |
| reports/{id} | 通報者、対象、定型理由、処理状態 |
| operationKeys・usageLimits | 再送防止とUID別の日次上限 |

上記は概念設計。より少ないコレクションで同じ要件を満たせるなら変更可。新しいインフラを増やさない。

フレンド共有の送信先の解除を大規模な全件走査で処理しない。関係ID・世代検証や受信者インデックスなど、上限内で確実に失効できる構造を選ぶ。必要なFirestoreインデックスをコード管理する。

## 10. APIの目安

| API | 認証・用途 |
| --- | --- |
| PUT /api/me | 認証必須、プロフィール初期化・更新 |
| GET /api/me | 本人の最小プロフィール |
| POST /api/shares | 認証必須、Web共有作成 |
| GET /api/shares | 本人の共有一覧。ページング |
| DELETE /api/shares/{id} | 所有者のみ取消 |
| POST /api/shares/{id}/rotate | 所有者のみリンク再発行 |
| GET /api/public/shares/{token} | 匿名可、有効な共有の公開項目のみ |
| POST /api/invitations | 認証必須、招待発行 |
| DELETE /api/invitations/{id} | 招待者のみ取消 |
| GET /api/public/invitations/{token} | 仮名と有効状態のみ |
| POST /api/friend-requests | 認証必須、招待トークン／コードで申請 |
| POST /api/friend-requests/{id}/accept | 招待者のみ承認 |
| POST /api/friend-requests/{id}/decline | 招待者のみ見送り |
| DELETE /api/friend-requests/{id} | 申請者の取消 |
| GET /api/friends | 本人のフレンド・申請一覧。ページング |
| DELETE /api/friends/{id} | 当事者のみ解除 |
| POST・DELETE /api/blocks/{id} | 本人のブロック・解除 |
| POST・GET・DELETE /api/friend-shares | 認証・所有者／現在の受信権限を確認 |
| POST /api/reports | 認証必須の通報。匿名Web通報は別の制限付き経路 |
| DELETE /api/me | 再認証を伴うアカウント削除開始 |

ルート名は変更可。ただし匿名取得と本人向け管理を明確に分ける。全件一覧API、UIDから他人の統計を取得するAPI、メールからユーザーを検索するAPIは作らない。

- すべてHTTPS。書込操作はGETにしない。
- リクエスト上限、入力検証、所有者検証、ページ件数上限を設ける。
- UIDやownerの偽装、他人のIDへの差し替えに対処する。
- 無効・期限切れトークンを大量に試せないよう匿名APIにもレート制限を設ける。
- サーバーレスのメモリ変数だけでレート制限を完了扱いしない。持続する制限とVercelで使える機能の範囲を確認する。
- 書込の日次上限はFirestoreトランザクション等で競合しても守る。
- Bearerトークン認証を使い、CORSだけを認証・認可の代わりにしない。
- App Checkは追加防御の候補。認証やアクセス制御の代わりにはしない。初版で必須化するかは実機の成立性を確認して決める。

## 11. 暗号化・秘密情報

今回はHTTPSによる通信保護と、クラウド側の保存時暗号化を基本とする。独自の暗号化方式やE2EEは実装しない。運営が絶対に内容を読めないという説明をしない。ランダムリンクは暗号化ではなく、リンク所持者に閲覧を許可する仕組み。

Firebase Adminの秘密鍵・サービスアカウント認証情報はVercelのサーバー環境だけに保存する。iOS、ブラウザ、NEXT_PUBLIC変数、GitHub、ログへ入れない。GoogleService-Info.plist等のクライアント設定と、Admin秘密鍵を混同しない。

GoogleログインにDriveへの権限を付けない。バックアップ実装時に別途同意する。

## 12. 削除と失効

### 12.1 操作を分ける

- 個人履歴の削除：端末内記録のみ。作成済みスナップショットは別であると明示。
- 共有取消：選んだ共有リンク／限定カードを失効させる。
- フレンド解除：関係と閲覧権限を終了する。
- ログアウト：端末の認証状態を終了。サーバーの共有は残る。
- アカウント削除：クラウド上のプロフィール・共有・招待・フレンド関係等を削除する。

### 12.2 アカウント削除

アプリ内に実装する。操作前に影響と、個人履歴を端末に残すかを確認する。必要ならGoogleで再認証し、サーバーでも直近認証を検証する。

削除処理は、先にユーザー状態をdeletingにし、その所有者の公開取得・書込を拒否する。残存データがあっても共有を再表示させない。本人の共有・招待・関係・共有先を削除／失効し、最後にFirebase Authアカウントを削除する。

処理が失敗しても再試行できる設計にし、Authだけ先に消して管理不能にしない。無料サーバーレスの実行時間を超える場合は、小分けの再開可能な処理とする。削除中状態、再試行、最終完了を区別して表示する。

通報記録を保持する必要がある場合は、最小限・保持期限・識別情報の匿名化方針を明記する。全データを即時削除したと虚偽表示しない。

## 13. 無料構成と運用

- 当面は非商用試作。Vercel Hobbyで進める。
- Hobbyは「無料アプリなら必ず利用可」ではなく非商用条件である。広告・課金・商用化前に見直す。
- Firebase Sparkの無料枠内を目標にする。Firestoreの読取・書込・保存・転送の上限を現行公式資料で確認する。
- 使用量が少なければ月0円を目指せるが、無制限・永久無料とは約束しない。
- Cloud Functions、TTL自動削除、課金必須機能を追加しない。
- 期限判定は読取時。期限切れレコードの物理削除は、所有者管理時と運営の手動クリーンアップ手順で行う。運営スクリプトはまずdry-runで件数確認できるようにする。
- 一覧ページング、公開数上限、再送防止、1件集計スナップショットで通信を抑える。無意味なポーリング・閲覧ログ書込をしない。
- Webの閲覧が急増して無料枠を超えた場合、個人アプリは使い続けられ、共有だけが一時利用不可になる設計にする。
- コスト制御を理由に失効確認なしのキャッシュ配信へ変えない。
- VercelとFirebaseの使用量確認方法をSETUPに記す。通知や予算アラートだけで必ず課金を防げるとは説明しない。

## 14. 利用者が行う設定

既存の設定があれば再利用し、新規プロジェクトを重複作成しない。

1. Firebaseプロジェクト、Firestoreのリージョン・Sparkプランを確認。
2. iOSアプリのBundle IDを登録し、Googleログインを有効化。
3. GoogleService-Info.plistとGoogle OAuthのiOSクライアント、URL Schemeを設定。
4. Google同意画面・テストユーザー・公開状態を確認。実際に要求する権限はログイン用の最小限。
5. サーバー用認証情報を安全に用意しVercel環境変数へ設定。
6. WebのVercelプロジェクト、Root Directory、安定した本番用ドメインを設定。
7. iOSにAPIのベースURLを設定。プレビュー用URLへ個人データを誤送信しない。
8. App IDのprefix／TeamとBundle IDを確認し、AASAとAssociated Domainsを設定。
9. 問い合わせ・プライバシー説明・通報確認手順を用意。

新しい有料Appleアカウントの作成は不要。既存の開発チーム設定を確認する。サービスアカウントの秘密鍵をチャットへ貼らせない。

## 15. 検証と受け入れ基準

### 15.1 未ログイン・既存機能

- 起動してログインせずに個人機能を使える。
- サーバー未設定・オフライン・認証失効でも制限・待機を妨げない。
- ログイン後も過去履歴が勝手にアップロードされない。
- 従来の自動再制限・利用後確認・Phase 3が動く。

### 15.2 認証と認可

- Google認証の成功・取消・失敗・再ログイン・別アカウント。
- 偽造／期限切れ／別プロジェクト／失効トークンを拒否。
- 他人のshareId、requestId、UIDへ差し替えた操作を拒否。
- Firestoreクライアントの直接アクセスを拒否。
- 表示名にHTMLが含まれてもWebで実行されない。

### 15.3 Web共有

- 未選択項目・非公開情報がJSONレスポンスにも含まれない。
- 正しい期間・件数・分母、記録なし、少数記録、途中週。
- 作成の再送で重複しない。
- 期限切れ、削除、再発行後の旧リンクが直ちに次回取得から無効。
- ページHTML、API、CDN等の別経路から古い公開内容を取得できない。
- ブラウザ・LINEプレビューが公開操作を起こさず、統計をプレビューへ漏らさない。
- iPhoneとPCで表示。QR・共有シート・コピーが同じURLを使う。

### 15.4 フレンド

- 申請前、申請中、承認後で権限が異なる。
- 自己招待・期限切れ・使用済み・既存関係・ブロックを適切に処理。
- 二重申請、逆方向同時申請、同時承認、取消との競合で重複しない。
- 解除・ブロック後に既存カードを新規取得できず、再承認で過去権限が復活しない。
- 無関係者・公開先にいないフレンドは読めない。
- 新しいフレンドに過去カードを自動公開しない。
- 通報を他人から読めない。

### 15.5 アカウント削除・実機

- 削除途中の失敗・再試行で共有が復活しない。
- アカウント切り替えでキャッシュ・保留操作が混ざらない。
- インストール済み／未インストール、LINE内ブラウザ、コード入力を確認。
- Firebase Dynamic Linksなしで動く。
- 実機未確認・本番環境未設定を明記する。

APIはモックだけでなくFirebase Emulator等を使い、2ユーザー＋第三者のアクセス権限と競合を検証する。実装と同じ条件式を写すだけのテストではなく、拒否されるべき操作を実際に試す。
