# 制限の一時停止・制限画面（シールド）・記録の集計

最終更新：2026-10-30。**ロジックのテストと、署名なしの実機向けビルド（Debug／Release）は通っています。実機での動作は、まだ確認していません。**

## 1. 制限全体の一時停止

### 手順
```
通常の制限中 ──「制限を一時停止」──▶ 待機（10分・前面のあいだだけ進む。制限は続く）
        ▲                                  │ 終わっても、自動では解除しない
        │                                  ▼
 自動で再制限 ◀── 30分 ◀── 本人が「30分間停止する」を押した時刻から数える
 （Device Activity拡張）
```
- 入口は、設定 → 制限 → いちばん下の **「制限の管理」**（探せないほど隠さず、ふだんの操作から離して置く）。
- 待機の開始時点では、何も解除しない。待機が終わっても、押すまで解除しない。
- 待機が終わってから **10分以内** に押さなければ、待機からやり直し。
- 待機を途中でやめる／放置（1時間）すると、進みは引き継がない（やり直し）。
- 停止中に「停止の時間を延ばす」「再停止」をするときも、待機（10分）を通る。延長は、押した時刻から30分。
- 停止の再開（制限を戻す）は、強める操作なので、待機なしでいつでもできる。
- 恒久的な「制限を終了する」は、別の項目として「制限の管理」の下部に置き、確認のダイアログを出す。

### 待機のルール
- アプリが前面の間だけ進む（バックグラウンド・画面ロックでは止まる）。残りは保存し、再起動しても飛ばせない・巻き戻らない。
- Debugビルドだけ、確かめやすいよう待機を15秒にしている（Releaseは10分）。停止の長さは30分のまま。

### 自動で制限に戻す仕組み
1. 先に状態（停止前の制限対象・終了時刻）を保存する。
2. Device Activity の監視（区間の終わり = 30分後）を登録する。
3. **1・2が成功したときだけ**、制限を外す。失敗したら、制限は外さず、理由と再試行を案内する。
4. 区間が終わると、拡張（FutoMonitor）が停止前の制限へ戻す。
5. 保険：アプリが前面に戻ったときに、期限を過ぎている・監視が消えている場合は、アプリ側で再制限する。

### 優先順位・競合
- 停止が始まったら、進行中の通常の一時解除は終える（監視と記録を消す）。停止中は、通常の一時解除を始められない。
- 拡張は、**現在の区間の名前と一致するイベントだけ**を処理する。延長で置き換えた古い区間・古い一時解除のイベントは無視する。
- 一時解除の再制限処理は、停止中は何もしない（停止の状態を上書きしない）。
- 停止中は、制限対象の追加・削除をしない（停止前の設定へ確実に戻すため）。
- 実際の制限がかかっている間は、デモへの切り替えもできない（切り替えで制限全体が外れる抜け道になるため）。

### 制限対象の「外す」（ゴミ箱）
- 対象を外せるのは、**制限をオフにしている間だけ**。一時解除中・一時停止中は外せない（以前は一時解除中に外せたが、待機を通らずに外せてしまうため、やめた）。
- ゴミ箱は「制限の対象から外す」だけで、アプリは削除されない（画面にも書いた）。

### OS上で保証できないこと
- 再制限は、OSが拡張を呼ぶ時刻に依存する。**厳密な時刻や、必ず呼ばれることは保証されない**（遅れることがある）。
- 端末の時刻・タイムゾーンを変えた場合の挙動は、OSの時刻の扱いに従う。時刻を進めると早く戻り、戻すと長く停止したままになる可能性がある（アプリの保険は、時刻を戻した場合を防げない）。
- **本人がiPhoneの設定でScreen Timeの許可を取り消すことは、防げない。**
- OS上でシールドが実際に出ているかは、アプリから確認できない（本アプリ用ストアの内容を照合するだけ）。

## 2. 開発専用の即時解除（Debugのみ）
- ホーム下部の「開発用：今すぐ制限解除」。待機を省略し、通常の一時解除・一時停止の監視と状態もすべて消して、制限を外す。
- 記録（Session）を作らないので、見送り・利用実績には数えない。
- `#if DEBUG` の中だけに存在する。**Releaseのバイナリに、ボタンの文言が含まれないことを確認した**（署名なしのReleaseビルドで検索）。

## 3. 制限画面（シールド）
- 追加ターゲット：`FutoShield`（Shield Configuration）、`FutoShieldAction`（Shield Action）。同じ開発チーム、Bundle ID は `com.ryouy.futo.shield` / `.shieldaction`、権限は Family Controls のみ（App Groupは不要）。
- 現在のSDK（iOS 18.5）で変えられるのは、背景色・ぼかし・アイコン・タイトル・説明・主／副ボタンの文言と色だけ。フォントはOSが決める。自由なSwiftUIや待機タイマーは置けない。
- 見た目：生成り（ダークは深い緑）の背景、ロゴ、緑のボタン。
- 文言：
  - タイトル「使う前に、ひと呼吸。」
  - 説明「今、何に使いたいですか。『ふと』で少し立ち止まれます。／ホーム画面から「ふと」を開いてください。」
  - ボタン「**ホームに戻る**」（実際の動作＝`ShieldActionResponse.close` と一致）
- **本体アプリをシールドから直接開く公式APIは、SDKに存在しない**（`ShieldActionResponse` は `none` / `close` / `defer` のみ）。そのため「ふとを開く」ボタンは作らず、説明文でホーム画面から開くよう案内している。
- 端末の言語が日本語なら日本語、それ以外は英語。

### 実機で確認する項目（未確認）

- 新しい拡張のBundle IDに、Family Controls が付くか（開発では自動で付く想定。配布には、拡張ごとにAppleの承認が必要になる可能性がある）。

## 4. 記録：日ごと・アプリごと
- 初期表示は、日付ごと → アプリごとに1行（「◯回」）。行を開くと、1回ごとの時刻・目的・解除時間・感想。
- 名称は「**一時解除◯回**」（実際の使用回数は取得できないため、「使用」とは呼ばない）。
- 数えるのは、一時解除を実際に始めたひと呼吸だけ。見送り・中断・解除に失敗したもの・制限全体の一時停止・開発用の解除は含まない。
- 日付は現地時刻の0時で区切る（UTCではない）。デモと実機は分ける。
- 解除した対象を記録していない古い記録は「対象の記録なし」と表示する（名前を推測しない）。
- 元の記録（時刻など）は削除しない。時間帯の分析と、共有する統計の定義は変えていない。
