## 実装済み

### Phase 0（デモ。Screen Timeは呼ばない）
- 初回説明、ホーム、目的選択、待機（標準180秒）、最終選択、結果、履歴、設定
- 待機：前面（`scenePhase == .active`）の区間のみ、単調増加時計の差分で進行。非アクティブ化時に残り時間を保存、再開で続きから
- 中断・再開（同じSession）、「この振り返りを終了」（中断として記録）
- SwiftData（Session）、日別件数（現地カレンダー、デモ／実機分離）、全削除（進行中は中断で閉じてから削除）
- デモ専用の架空アプリ選択、全画面上部の常時デモ表示
- 待機はDebugビルドで自動的に10秒、Releaseで180秒（切り替えUIなし）

### Phase 1（実機。署名・Capability設定後に利用可能）
- 個人向け認証（`AuthorizationCenter.requestAuthorization(for: .individual)`）
- `FamilyActivityPicker` による選択（初版はアプリのみだったが、現在はカテゴリ・ウェブサイトも可。下記）
- `ManagedSettingsStore` に本アプリ専用の名前を付け、`shield.applications` で制限の開始／終了
- 権限・保存した意図・ストアの内容を照合して状態表示（「確認不能」あり）。前面復帰時に再確認
- 権限を失った場合は進行中の振り返りを中断して案内
- 制限中・待機中は対象変更不可。実機→デモ切替前に実際の制限を終了（確認できなければ切替を保留）

### Phase 2（実機のみの試験機能。App Groupと拡張の設定が必要）
- 「使いたい」の後に解除するアプリを1つ以上選び、そのアプリだけ一時解除（選ばれなかったアプリは制限を維持）：Device Activityの監視（16分の区間＋選んだアプリの利用しきい値。Releaseは5分、Debugは1分）を登録できた場合だけ解除。失敗時は制限を維持
- 拡張 `FutoMonitor`：しきい値到達または区間終了で再制限。現在の解除に対応しない古い・重複イベントは無視
- 本体：前面復帰時に、監視が無い・区間を過ぎているのに解除が残っていれば再制限（安全側の補正）。ホームの「制限に戻す」
- 共有状態：App Group（`SharedState`）。App Groupが使えないと一時解除は無効になり、Phase 1の動作に戻る
- 一時解除のあと（再制限されたあと）、ホームに「さっきの時間は、どうでしたか？」を1回だけ表示。選択肢3つ＋「答えない」。履歴にも表示（利用者の依頼で追加。仕様書の初版範囲外）
- デモでは一時解除を行わない（記録のみ）
- 手動の「制限を終了」は一時解除として記録しない

### Phase 3（[phase3.md](phase3.md)。利用者の依頼で、仕様書の初版範囲から拡張）
1. **朝夜の振り返り**：ホームに、設定した時刻から約6時間、カードを表示。昨日（朝）／今日（夜）の記録だけを使った定型文で、評価・気持ちの推測・称賛をしない。記録が無いときは中立的な一文。カードは `ReflectionCard`（SwiftData）に保存し、起動ごとに作り直さない。閉じられ、催促しない。朝・夜それぞれ時刻の変更・無効化が可能。日の区切りは午前4時（深夜0〜4時は前日に数える）。**開発中は昨日の記録が無いため、Debugビルドでは朝も今日の記録で作る**。Debugのホームに「朝／夜の振り返りをいま見る」ボタン。
2. **今週の傾向**：ホームの履歴アイコン→「今週」。目的の内訳、利用後の感想の内訳（回答件数を併記。「答えない」は除外）、「使いたい」「今はやめる」「感想に答えた」「一時解除を始めた」の件数、記録が多い時間帯。実利用の確認できない解除を使用済みとして扱わず、使用時間・節約時間・開こうとした回数は出さない。前週比較は両週に記録があるときだけ、良し悪しを断定しない。デモと実機は分離。
3. **設定改善の提案**：週1回まで、関連する記録が5件以上あるときだけ、既存設定（待機時間、夜の振り返り時刻）に限った提案を1つ。「変更する」（現在値→変更後の値を確認してから適用）／「今のまま」（同じ提案を28日出さない）／「今回は見送る」（その週は出さない）。自動変更しない。
4. **通知（ローカル）**：初期はすべてオフ。夜の振り返りを推奨。有効にするときに用途を説明してからOSの許可を求める（拒否されても基本機能は使え、繰り返し迫らない）。朝／夜／使ったあとの確認／お出かけを個別にオン・オフ、時刻指定。1日最大4件、3時間以上の間隔、静かな時間（既定22時〜翌8時、変更可）は送らず翌朝にまとめもしない。朝夜が衝突したら設定画面で知らせて間引く。見た振り返りの通知は予約しない。音・バッジなし。ロック画面は定型文のみ。予約は `NotificationPlanner` に一本化し、アプリを開くたびに今日・明日分を組み直す。通知タップでホームへ（朝夜は該当カード）。Debugのホームに「お出かけ通知を3秒後に送る」ボタン。
- **設定**：待機時間（1〜10分。Debugは10秒も）を設定で変更可能。既定はReleaseが3分、Debugが10秒。

**Phase 3 の既知の制約（正直な報告）**
- 利用後の確認通知は、一時解除の開始時に「監視区間の終了時刻」へ予約する近似。実際の再制限（しきい値到達）の時刻は本体から分からず、拡張からの通知予約は実装していない。回答済み・時刻超過・対象不明の予定は作らない。朝夜通知と近い場合は追加せず、アプリ内のカードで確認する。
- OSは指定時刻ぴったりの配信を保証しない。バックグラウンド処理を前提にしていない。
- 振り返りカードの「朝」を本番（昨日の記録）で見るには、翌日以降のデータが必要。

### 画面・導線の見直し（利用者の依頼）
- 履歴：結果を「やめた／解除した／使いたいと答えた／途中でやめた」で表示し、目的、**解除していた時間**（「解除 約3分」。使った時間ではない。解除中は「解除中」）、解除したアプリ、感想を必要な分だけ表示。解除の終了時刻は、拡張・本体のどちらが再制限しても `SharedState` に記録し、本体が履歴へ反映する。
- グラフ画面は廃止（履歴と重複するため）。記録の画面に統合した（下記）。
- ホームの「今日やめた」「今日使いたかった」はボタン。押すと今日の該当記録と、解除したアプリ別の回数・解除時間。
- 「ひと呼吸を続ける」（再開）機能を廃止。ひと呼吸の画面から出るのは「ひと呼吸をやめる」のみ。画面の外に残った進行中のひと呼吸（再起動など）は、起動時に中断として閉じる。仕様書の「中断してホームへ戻れる／再開」から変更。
- 制限するアプリは縦の行。南京錠は一時解除中のアプリにだけ付く（閉じた錠と、変更不可の錠は廃止）。
- 画面の切り替えは「先に消え、次に現れる」順で、重ならない。

### 朝夜の振り返りの文言・グラフ・ホームの調整（利用者の依頼）
- 振り返りの文章は、数を並べず「少なめ／何回か／多め」「中心／いろいろ」のような抽象的なプリセットに。記録の量・結果の偏り・目的の偏り・感想の偏りで場合分けし、言い回しは同じ日・同じ記録なら同じになる（保存もする）。朝は「はじまり」、夜は「ひと区切り」の言葉。詳細は結果・目的・（感想または解除）の最大3行＋締めの一文。
- 目的と感想は円グラフ（凡例で見分ける）。
- ホーム：アプリ一覧は縦の行に戻した（5つ以上のときだけ欄の中でスクロール）。「やめた」「使いたかった」は小さなボタン（「今日」の語は削除、中身は今日の記録）。開発用ボタンは小さく。

### 記録画面の統合・ホームの1画面化（利用者の依頼）
- **記録**：履歴とグラフを1画面にまとめ、上で「今週／今月／すべて」を切り替える。中身は、件数（ひと呼吸／やめておく／使いたい／感想に答えた／解除した＋解除時間）、目的と感想の円グラフ、時間帯（朝・昼・夕方・夜。何時かは出さない）、記録の一覧。説明の注釈と、前週比較は廃止。「選んだ」の語も外した。記録の一覧の解除したものは、アイコンだけ（名前なし）。
- **朝の振り返り**は必ず「昨日は、」で始まる（開発中は今日の記録で作るが、言い方は昨日）。
- **ホーム**：1画面に収め、通常は上下にスクロールしない（朝夜のカードが加わって収まらないときだけ全体をスクロール）。状態の錠と領域を小さくし、「押すと、すぐ制限に戻ります。」は削除。制限するものが4つ以上のときは、欄の中だけをスクロールし、4行目を半分見せて下端をぼかし、矢印で伝える（一番下まで行くと消える）。

### 起動・初回説明・ホームの調整（利用者の依頼）
- **スプラッシュ**：起動時に約1秒、OSの起動画面と同じ画像をアプリ内でも表示し、フェードで消す（`SplashView`）。
- **初回の説明**：スプラッシュと同じ深い緑のまま、4ページ＋「はじめましょう」の複数ページ（ロゴ／ふだんは制限／使いたいときはひと呼吸／そっと振り返る）。インジケータ（現在のページが伸びる点）、「つぎへ」「スキップ」、ページごとにふわっとフェード。最後に「実機で設定する」「デモで試す」。ロゴは提供のアイコン画像から背景を透過して作成（`Logo.imageset`）。
- **ホーム**：制限するものの表示数を、画面の高さに応じて3〜6件に自動調整（余裕があれば最大6件、超えたらその欄の中でスクロール）。「やめた／使いたかった」はホームから外し、記録画面の上部に小さく表示（「今日 やめた 2 使いたかった 1」）。押して開く「今日の記録」画面は廃止。

### 通知の不具合修正・設定のタブ化・解除まわり（利用者の依頼）
- **通知が出なかった原因（コードで確認して修正）**：①通知の優先度を「パッシブ」にしていたため、バナーが出ず通知センターにだけ入っていた → 通常の優先度（音・バッジなしのまま）に変更。②開発用テスト通知の識別子が `futo.` で始まり、定期通知の予約し直し（前面復帰のたびに実行）で消されていた（許可ダイアログを閉じた直後に起きる）→ `debug.test.` に変更。前面表示中もバナーを出す。**実機での受信は未確認**。設定の通知タブ（Debugのみ）に、許可状態と予約中の通知の一覧を表示。
- **設定をタブ化**（制限／ひと呼吸／通知／その他）。各タブが1画面に収まる量に。説明文を短縮。
- **解除のラグ**：選択画面のラベルを毎回作り直さない・アイコンを再描画しない対策、「解除する」を押したら先に「解除しています…」へ切り替えてからOSへ設定する。**体感の改善は実機未確認**。
- 「解除しました」画面：「〇分ほど、ゆっくりどうぞ。戻ってきたら、感想を教えてください。」。「今も使いたいですか？」は「使いたい」を濃い色、「やめておく」を薄い色にし、下の小さな文を削除。
- ホームの制限するものは最大8件。画面全体で、折り返さず1行に収まるよう文言を短縮（収まらないときは少し縮小）。

### 主ボタンの見直し・凡例・ラベル（利用者の依頼）
- **主ボタンの考え方**：「ふだんは制限中」が基本なので、制限を強める操作は濃い色、緩める入口は薄い色にして、解除を前面に出しすぎない。位置は、状態カードの真下（画面の最下部へ離さない）。
  - 制限中：「ひと呼吸おいて、使う」（薄い色）／ 一時解除中：「使い終わる」／ 制限していない：「制限をかける」／ 許可なし：「許可する」／ 未選択：「制限するものを選ぶ」／ 確認不能：「制限をかけ直す」。
  - 「オン／オフ」をやめ、「かける／はずす」に統一（設定の「いつも制限する」をはずすときは確認つき）。状態の一言は「制限していません」。
- 感想の選択肢「もう少し控えたかった」を「使いすぎかも」に変更（保存値は変わらない）。
- 円グラフの凡例は、グラフの横に小さく縦並び（0件の項目は出さない）。

### 設定タブ・テーマ・解除時間（利用者の依頼）
- 設定のタブは、記録画面と同じ上部の切り替え（制限／ひと呼吸／通知／その他）。
- テーマカラーは4色（深緑・空・桜・藤）。以前「夕焼け」を選んでいた場合は、深緑に戻る。
- **解除する時間**：設定（ひと呼吸）で1〜30分から選べる（既定はReleaseが5分、Debugが1分）。「その分だけ使うと制限に戻る」しきい値として Device Activity に登録する。Appleの監視区間は最短15分のため、区間は max(分数+1, 16)分。したがって、短い設定でも、使わなければ最長16分は解除されたままになり、30分の設定では、使わなくても約31分で必ず戻る。**実機未検証**（特に、15分を超えるしきい値と区間の組み合わせ）。

### お出かけ通知の文言（利用者の依頼）
- 「外に出て、少し歩いてみませんか。」に加えて、のんびりした誘いかけを10個追加（計11個。窓を開けて深呼吸、空を見上げる、温かい飲み物、のび、いつもと違う道、近くの木や花、水を一杯、目を閉じてひと呼吸、今日の空の色、近所をひとまわり）。予約するときに、日ごとに1つが決まる（同じ日は同じ文言）。Debugの「お出かけ通知」は押すたびに変わる。評価・不安・連続記録の言葉や数字は入れない（テストで確認）。

### ホームの＋・初回説明の再表示（利用者の依頼）
- ホームの「制限しているもの」の見出しを削除。「＋」は状態の行（錠と一言の行）の右端の円形ボタンに移し、追加の高さを取らない（変更できる間だけ表示）。
- **Debug限定**：設定（その他）に「初回説明をもう一度表示」。戻すのは「説明を見た」フラグだけで、履歴・制限の設定・動作モードは変えない。見直し中は最後のページが「閉じる」だけになり、モード選択で実機の制限が外れるような副作用は起きない。Releaseにはコードごと含まれない（`#if DEBUG`）。このアプリにログインは無い。

### 説明からホームへの遷移・ホームのチュートリアル（利用者の依頼）
- 初回説明からホームへは、他の画面と同じ「先に消えて、次が現れる」ゆっくりしたフェードで切り替わる。
- **チュートリアル**：ホームが現れてから、画面を暗くして場所を順に光らせ、吹き出しで「どこを押すとどうなるか」を説明する（状態の欄／＋（見えているときだけ）／主ボタン（状態に合わせた文言）／右上の記録と設定／準備はできました）。「つぎへ」「スキップ」「はじめる」。初回（説明を終えたあと）に1回だけ流れ、Debugの「初回説明をもう一度表示」からは、説明ページのあとにチュートリアルまで続けて流れる。すでに使っている端末では、次の起動で1回だけ流れる。
- 実装：光らせる場所は `anchorPreference` で集める。右上の記録・設定は、ナビゲーションバーに属するため、位置を画面の右上から近似している。**位置のずれ・遷移の見え方は実機未確認**（ずれた場合は端末を教えてください）。

## 利用者の依頼による仕様書からの変更（文言・配置）
- 「今日の見送り／利用希望」を「今日やめた／今日使いたかった」に変更（意味は同じ）。「振り返り」は「ひと呼吸」に統一。
- 対象の変更は設定からホームのアプリ欄へ移動：右上の「＋」で追加、各アプリの「－」で制限から外す。変更できるのは制限がかかっていない間（制限オフ、または一時解除中）だけで、制限中は南京錠のみ表示（仕様書の「制限中・待機中の対象変更は禁止」を、待機中は許可・一時解除中は許可に変更）。一時解除中に追加したアプリは制限される。
- 一時解除したアプリはホームで開いた南京錠と「解除中」を表示。履歴にはそのアプリ（OSの不透明なトークンを端末内に保存し、表示時にOSのラベルで描画。名前は保存しない）を表示。
- 「ひと呼吸を終える」は「ひと呼吸をやめる」に改称。待機画面の戻る操作は「ホーム」とし、再開できる旨を表示。
- 「記録しました」の「ホームへ」は「閉じる」に変更。選んだアプリへ飛ぶボタンは作れない（Screen Timeの対象は不透明なトークンで、アプリを起動するAPIがない）。

## 見た目・操作の追加（利用者の依頼）
- 画面遷移をゆるやかに：ひと呼吸の画面は、下からせり上がらずフェードと小さな拡大で現れる。画面内の切り替えはゆっくり重なる。履歴・設定・アプリ選択はカード状のシート。
- 動きの調整：浮かび上がる拡大・移動をやめ、短いフェードに統一し、速度を約1.5倍に。待機の円とタイマーは毎フレーム時計から描画し滑らかに。待機の前に所要時間を伝え（目的選択画面と待機画面）、言葉のあとにタイマーを現す。
- テーマカラー（若葉・空・桜・藤・夕焼け）を設定で選べる。端末内に保存。
- 検証：型検査のみ。見た目・アニメーションは実機未確認。

### カテゴリ・ウェブサイトの制限、ホームの作り替え、スプラッシュ（利用者の依頼）
- **制限するもの**：アプリに加えて、カテゴリとウェブサイトも制限・一時解除できる（仕様書の初版範囲外だったものを、利用者の依頼で追加）。`ManagedSettingsStore` の `shield.applications` / `applicationCategories` / `webDomains` を使う。一時解除したアプリは、制限中のカテゴリの例外（`except:`）にする。履歴には、解除したアプリ・カテゴリ・サイトをOSのラベルで表示（トークンを端末内に保存。名前は保存しない）。
- **「いつも制限する」を基本に**：ホームは中央に大きな錠と一言（制限中／一時的に使えます／制限はオフです）。主操作は「使う前に、ひと呼吸」だけで、制限をオフにする操作はホームから外し、設定の「いつも制限する」（オフは確認つき）へ。制限を始める操作は「制限をオンにする」。選択の保存だけでは勝手に制限を始めない（従来どおり）。
- **言い回しの改善**：制限を終了→「制限をオフにする」、制限に戻す→「使い終わる」（押すとすぐ制限に戻ると明記）、制限を始める→「制限をオンにする」、ひと呼吸をやめる→「やめてホームへ」、今はやめる→「やめておく」、制限するアプリ→「制限しているもの／制限するもの」、どのアプリを使いますか→「どれを使いますか？」。
- **スプラッシュ**：提供画像（853×1844）を全画面の起動画面に（`LaunchScreen.storyboard`、`docs/assets/splash-source.png`）。デフォルトのテーマ色を #196459（名前は「深緑」）に変更。
- 検証：型検査とロジックのユニットテストのみ。起動画面は `ibtool` でコンパイルできることを確認（Xcodeでのビルド・実機表示は未確認）。カテゴリ／ウェブサイトのシールド表示と一時解除は**実機未検証**。

## 既知の制約・メモ
- 初版は、制限をホームから手動で終了できる設計。解除不能を目指していない。
- ホームの状態表示は権限と設定の照合結果で、OS上でシールドが出ているかを常時検知しない。
- 目的選択で「戻る」を押すと、まだ始まっていないSessionは破棄される（中断としては記録しない）。
- 待機の保存は非アクティブ化時。クラッシュ時は直前に保存した残り時間まで戻る（待機が延びる側）。
- `PRODUCT_BUNDLE_IDENTIFIER`（`com.ryouy.futo`）は仮の値。`DEVELOPMENT_TEAM` は空欄。
- 本番ビルドに待機短縮の手段は存在しない（`#if DEBUG`）。
- Phase 2の既知の不確実点（実機で要確認）：Appleの監視区間は最短15分のため、利用がしきい値に達しない場合の再制限は区間終了（約16分後）になる。しきい値が解除前の利用を含まないか、強制終了・再起動後に再制限されるかは未確認。通常のTimerや通知で代用していない。
- App Groupのidは `group.<Bundle ID>`。Bundle IDを変えたらentitlementsも変更が必要（`SETUP.md`）。
