# 実装状況（Phase 0 / 1 / 2 / 3）

最終更新：2026-10-29。仕様：[Futo_Claude_MVP_Spec.md](Futo_Claude_MVP_Spec.md)

## 実装済み

### Phase 0（デモ。Screen Timeは呼ばない）
- 初回説明、ホーム、目的選択、待機（標準180秒）、最終選択、結果、履歴、設定
- 待機：前面（`scenePhase == .active`）の区間のみ、単調増加時計の差分で進行。非アクティブ化時に残り時間を保存、再開で続きから
- 中断・再開（同じSession）、「この振り返りを終了」（中断として記録）
- SwiftData（Session）、日別件数（現地カレンダー、デモ／実機分離）、全削除（進行中は中断で閉じてから削除）
- デモ専用の架空アプリ選択、全画面上部の常時デモ表示
- 待機はDebugビルドで自動的に10秒、Releaseで180秒（切り替えUIなし）

### Phase 1（実機。署名・Capability設定後に利用可能）
- 個人向け認証（`AuthorizationCenter.requestAuthorization(for: .individual)`）
- `FamilyActivityPicker` によるアプリ単位の選択。カテゴリ・Webサイトを含む場合は保存せず選び直しを案内
- `ManagedSettingsStore` に本アプリ専用の名前を付け、`shield.applications` で制限の開始／終了
- 権限・保存した意図・ストアの内容を照合して状態表示（「確認不能」あり）。前面復帰時に再確認
- 権限を失った場合は進行中の振り返りを中断して案内
- 制限中・待機中は対象変更不可。実機→デモ切替前に実際の制限を終了（確認できなければ切替を保留）

### Phase 2（実機のみの試験機能。App Groupと拡張の設定が必要）
- 「使いたい」の後に解除するアプリを1つ以上選び、そのアプリだけ一時解除（選ばれなかったアプリは制限を維持）：Device Activityの監視（16分の区間＋選んだアプリの利用しきい値。Releaseは5分、Debugは1分）を登録できた場合だけ解除。失敗時は制限を維持
- 拡張 `FutoMonitor`：しきい値到達または区間終了で再制限。現在の解除に対応しない古い・重複イベントは無視
- 本体：前面復帰時に、監視が無い・区間を過ぎているのに解除が残っていれば再制限（安全側の補正）。ホームの「制限に戻す」
- 共有状態：App Group（`SharedState`）。App Groupが使えないと一時解除は無効になり、Phase 1の動作に戻る
- 一時解除のあと（再制限されたあと）、ホームに「さっきの時間は、どうでしたか？」を1回だけ表示。選択肢3つ＋「答えない」。履歴にも表示（利用者の依頼で追加。仕様書の初版範囲外）
- デモでは一時解除を行わない（記録のみ）
- 手動の「制限を終了」は一時解除として記録しない

### Phase 3（[phase3.md](phase3.md)。利用者の依頼で、仕様書の初版範囲から拡張）
1. **朝夜の振り返り**：ホームに、設定した時刻から約6時間、カードを表示。昨日（朝）／今日（夜）の記録だけを使った定型文で、評価・気持ちの推測・称賛をしない。記録が無いときは中立的な一文。カードは `ReflectionCard`（SwiftData）に保存し、起動ごとに作り直さない。閉じられ、催促しない。朝・夜それぞれ時刻の変更・無効化が可能。日の区切りは午前4時（深夜0〜4時は前日に数える）。**開発中は昨日の記録が無いため、Debugビルドでは朝も今日の記録で作る**。Debugのホームに「朝／夜の振り返りをいま見る」ボタン。
2. **今週の傾向**：ホームの履歴アイコン→「今週」。目的の内訳、利用後の感想の内訳（回答件数を併記。「答えない」は除外）、「使いたい」「今はやめる」「感想に答えた」「一時解除を始めた」の件数、記録が多い時間帯。実利用の確認できない解除を使用済みとして扱わず、使用時間・節約時間・開こうとした回数は出さない。前週比較は両週に記録があるときだけ、良し悪しを断定しない。デモと実機は分離。
3. **設定改善の提案**：週1回まで、関連する記録が5件以上あるときだけ、既存設定（待機時間、夜の振り返り時刻）に限った提案を1つ。「変更する」（現在値→変更後の値を確認してから適用）／「今のまま」（同じ提案を28日出さない）／「今回は見送る」（その週は出さない）。自動変更しない。
4. **通知（ローカル）**：初期はすべてオフ。夜の振り返りを推奨。有効にするときに用途を説明してからOSの許可を求める（拒否されても基本機能は使え、繰り返し迫らない）。朝／夜／使ったあとの確認／お出かけを個別にオン・オフ、時刻指定。1日最大4件、3時間以上の間隔、静かな時間（既定22時〜翌8時、変更可）は送らず翌朝にまとめもしない。朝夜が衝突したら設定画面で知らせて間引く。見た振り返りの通知は予約しない。音・バッジなし。ロック画面は定型文のみ。予約は `NotificationPlanner` に一本化し、アプリを開くたびに今日・明日分を組み直す。通知タップでホームへ（朝夜は該当カード）。Debugのホームに「お出かけ通知を3秒後に送る」ボタン。
- **設定**：待機時間（1〜10分。Debugは10秒も）を設定で変更可能。既定はReleaseが3分、Debugが10秒。

**Phase 3 の既知の制約（正直な報告）**
- 利用後の確認通知は、一時解除の開始時に「監視区間の終了時刻」へ予約する近似。実際の再制限（しきい値到達）の時刻は本体から分からず、拡張からの通知予約は実装していない。回答済み・時刻超過・対象不明の予定は作らない。朝夜通知と近い場合は追加せず、アプリ内のカードで確認する。
- OSは指定時刻ぴったりの配信を保証しない。バックグラウンド処理を前提にしていない。
- 振り返りカードの「朝」を本番（昨日の記録）で見るには、翌日以降のデータが必要。

## 利用者の依頼による仕様書からの変更（文言・配置）
- 「今日の見送り／利用希望」を「今日やめた／今日使いたかった」に変更（意味は同じ）。「振り返り」は「ひと呼吸」に統一。
- 対象の変更は設定からホームのアプリ欄へ移動：右上の「＋」で追加、各アプリの「－」で制限から外す。変更できるのは制限がかかっていない間（制限オフ、または一時解除中）だけで、制限中は南京錠のみ表示（仕様書の「制限中・待機中の対象変更は禁止」を、待機中は許可・一時解除中は許可に変更）。一時解除中に追加したアプリは制限される。
- 一時解除したアプリはホームで開いた南京錠と「解除中」を表示。履歴にはそのアプリ（OSの不透明なトークンを端末内に保存し、表示時にOSのラベルで描画。名前は保存しない）を表示。
- 「ひと呼吸を終える」は「ひと呼吸をやめる」に改称。待機画面の戻る操作は「ホーム」とし、再開できる旨を表示。
- 「記録しました」の「ホームへ」は「閉じる」に変更。選んだアプリへ飛ぶボタンは作れない（Screen Timeの対象は不透明なトークンで、アプリを起動するAPIがない）。

## 見た目・操作の追加（利用者の依頼）
- 画面遷移をゆるやかに：ひと呼吸の画面は、下からせり上がらずフェードと小さな拡大で現れる。画面内の切り替えはゆっくり重なる。履歴・設定・アプリ選択はカード状のシート。
- 動きの調整：浮かび上がる拡大・移動をやめ、短いフェードに統一し、速度を約1.5倍に。待機の円とタイマーは毎フレーム時計から描画し滑らかに。待機の前に所要時間を伝え（目的選択画面と待機画面）、言葉のあとにタイマーを現す。
- テーマカラー（若葉・空・桜・藤・夕焼け）を設定で選べる。端末内に保存。
- 検証：型検査のみ。見た目・アニメーションは実機未確認。

## 既知の制約・メモ
- 初版は、制限をホームから手動で終了できる設計。解除不能を目指していない。
- ホームの状態表示は権限と設定の照合結果で、OS上でシールドが出ているかを常時検知しない。
- 目的選択で「戻る」を押すと、まだ始まっていないSessionは破棄される（中断としては記録しない）。
- 待機の保存は非アクティブ化時。クラッシュ時は直前に保存した残り時間まで戻る（待機が延びる側）。
- `PRODUCT_BUNDLE_IDENTIFIER`（`com.ryouy.futo`）は仮の値。`DEVELOPMENT_TEAM` は空欄。
- 本番ビルドに待機短縮の手段は存在しない（`#if DEBUG`）。
- Phase 2の既知の不確実点（実機で要確認）：Appleの監視区間は最短15分のため、利用がしきい値に達しない場合の再制限は区間終了（約16分後）になる。しきい値が解除前の利用を含まないか、強制終了・再起動後に再制限されるかは未確認。通常のTimerや通知で代用していない。
- App Groupのidは `group.<Bundle ID>`。Bundle IDを変えたらentitlementsも変更が必要（`SETUP.md`）。
